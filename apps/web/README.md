# @weavestream/web

Next.js App Router frontend for Weavestream.

## Replacing the logo

The app reads all branded imagery from static assets under
`apps/web/public/brand/`. To rebrand, drop the following files in place;
no rebuild is required — Next.js serves them statically.

| File | Used by | Notes |
| --- | --- | --- |
| `public/brand/logo-mark.svg` | Sidebar header, `<AppLogo variant="mark">` | Square, ~512×512. The sidebar renders it at 22 px; keep it legible at that size. |
| `public/brand/logo-wordmark-light.svg` and dark variant | Auth shell (login/setup), `<AppLogo>` default | Horizontal wordmark. Aspect ratio should stay close to 5:1 to avoid layout shifts — `AppLogo` caps the rendered width at `height * 7`. |
| `public/brand/logo.svg` | Reserved for marketing surfaces (docs, emails). The app itself does not import this file. | Optional. |
| `public/brand/pwa-icon-180.png` | iOS Home Screen icon | Opaque 180×180 PNG. Keep the mark centered and let iOS apply its own corner mask. |
| `public/brand/pwa-icon-192.png` | PWA manifest icon | Opaque 192×192 PNG with `purpose: any`. |
| `public/brand/pwa-icon-512.png` | PWA manifest icon | Opaque 512×512 PNG with `purpose: any`. |
| `public/brand/pwa-icon-maskable-512.png` | Maskable PWA icon | Full-bleed, opaque 512×512 PNG with important artwork inside the maskable safe zone. |

The favicon and social preview are generated by the App Router from
`src/app/icon.tsx` and `src/app/opengraph-image.tsx`. The iOS Home Screen
icon is linked explicitly from `src/app/layout.tsx`; the remaining install
icons are declared in `src/app/manifest.webmanifest`. After replacing an
installed icon, remove and re-add the Home Screen app because mobile
platforms cache install-time artwork aggressively.

## Theme + accent

Every user has a server-persisted theme (`dark | light | system`) and
accent (`lime | amber | iris | coral | teal`). See the Phase 9b.1 plan
for the full flow; the entry points are:

- `/me` Appearance panel — segmented control + swatch picker with live
  preview.
- Sidebar footer — one-click dark/light flip (authenticated).
- Login/setup shell top-right — same flip for unauthenticated users,
  persisted in the `ws_ui` cookie via `POST /public/ui-prefs`.
